Magic - Local AI Desktop Agent

A fully offline, deeply controllable local AI Agent for your computer. Supports file management, system operations, and tool calling with absolute privacy. No internet required.

Introduction

Magic is a Python-based local AI desktop assistant. Unlike standard chatbots, it can execute system commands and manipulate files through Tool Calling mechanisms.

It is the core component of the Rainbow OS ecosystem, but it is highly independent and can run as a standalone desktop AI assistant on any mainstream Linux distribution. Our core philosophy is to make AI the native brain of the system, not just an external chat window.

Core Features

100% Offline: Powered by local LLMs (scheduled via Ollama, e.g., Qwen2.5-VL). No cloud servers. Your conversations and commands never leave your computer, ensuring absolute privacy.

System Operations: Control your system via natural language—open applications, adjust volume, get time, take screenshots, lock screen, etc.

Full-stack File Management: Create, read, write, search, delete, copy, and move files/directories through conversation. It can even create nested directories.

Safety Mechanisms: To ensure system security, when the AI attempts to execute dangerous commands (like rm, mkfs, shutdown), the program pauses and requests user confirmation in the terminal.

Intelligent Routing: No hardcoded rules. The AI decides whether to respond conversationally or output JSON to call a tool.

Highly Extensible: Modular architecture. System tools and file tools are independent. Future extensions can be easily added by developers or even generated by the AI itself.

How it Works

Traditional voice assistants or dialogue scripts use regular expressions to guess user intent, which is brittle and fails if the phrasing changes.

The core philosophy of Magic is: The script doesn't guess user intent; the model makes the decision.

Workflow:

User inputs text (e.g., "Open Firefox").

The script sends the "Tool Manual" along with the user input to the local LLM.

The model analyzes and decides to output a JSON object (e.g., {"tool": "open_app", "name": "firefox"}).

The script receives the JSON, calls the underlying system.py module, and executes the command.

After success, the script returns the result to the model, which then replies to the user naturally (e.g., "Firefox is now open").

Directory Structure

magic/: Project root
core/: Core application directory
config.yaml: Global configuration (model name, context size, memory limits)
config_loader.py: Config loader
loop.py: Main loop entry, handles model communication and tool dispatch
模块/ (Modules)/: Tool modules directory
内部/ (Internal)/: Built-in core tools
system.py: System-level operations
file.py: File system operations
registry.py: Tool registry, informs AI of available tools
扩展/ (External)/: For future AI-generated custom modules
memory/: Memory system
short_term.py: Short-term memory (recent context)
long_term.py: Long-term memory (SQLite for user preferences)
backends/: LLM backend adapters
ollama_backend.py: Ollama API wrapper

Quick Start

Requirements: Linux (Debian/Ubuntu recommended), Python 3.10+, Ollama installed with model downloaded (e.g., qwen2.5vl:7b-q4_K_M).

Installation:

Install system dependencies: sudo apt install xclip xdotool wmctrl xbacklight gnome-screenshot -y

Setup virtual environment: python3 -m venv ai_env, then source ai_env/bin/activate

Install Python packages: pip install pyyaml requests

Run:
cd magic/core
python3 loop.py

Usage Examples

Normal Chat: "Hello, who are you?" -> Answers directly.
Time Query: "What time is it?" -> Calls get_time tool.
App Control: "Open Firefox" -> Calls open_app tool.
System Control: "Set volume to 30%" -> Calls volume tool.
File Operations: "Create file note.txt content Hello World" -> Calls create_file tool.
Command Execution: "Run ls -la" -> Calls run_command tool.
